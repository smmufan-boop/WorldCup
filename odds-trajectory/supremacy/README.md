# 新算法原型：隐含净胜球轨迹比对（Royal 亚盘）

与之前的算法无关，重新设计。只复用 `research/build_inputs.py` 的数据清洗（相同的报价、相同的已核验赛果），保证可以和以前的结果公平比较。

## 思路

亚盘每次变盘，水位都会跳变，水位序列不连续。本原型把每条报价（盘口 + 主客水位）换算成**隐含净胜球 μ**：假设主客进球服从独立泊松分布、总进球期望为 2.7，求出使去水后的价格恰好公平的预期净胜球（主减客）。

换算后，变盘不再是断点。例如平手盘主水 0.71 / 客水 0.99 → μ = +0.122；随后升盘到主让 0.25、主水 0.98 → μ = +0.147，前后连续。在 3,000 场 Royal 比赛上：

- 主队水位：换盘处的相邻变化是同盘处的 6.7 倍；
- 换算成 μ 后：只有 3.1 倍，剩下的大多是真实价格变动（庄家通常在价格变动较大时才变盘）。

欧指（主/平/客）以后可以换算到同一刻度，并多出"预期总进球"一个维度。

## 算法

| 步骤 | 内容 |
|---|---|
| 换算 | 每条 Royal 报价 → μ（预先算好查表，盘口 ±10 球以内） |
| 轨迹 | 取初盘和开赛前 1440、720、360、180、120、60、30、10 分钟时的 μ（取各时点之前最后一条报价），得到 8 段变化量，作为"形状" |
| 水平 | T−10 时的 μ |
| 变盘校正 | 发生在变盘处的 μ 变化之和、同一盘口内的 μ 变化之和、升盘次数、降盘次数 |
| 相似度 | 各特征按开发段标准差标准化后，计算加权欧氏距离 = 形状 + 水平权重 × 水平 + 校正权重 × 校正 |
| 预测 | k 个最近邻的**市场误差**均值。市场误差 = 实际净胜球 − T−10 的 μ；均值 > 0 表示同类比赛市场低估了主队 |
| 下注 | 按 T−10 的 Royal 报价买市场低估的一方；可以只做预测最强的 30% 或 10% |

**时间顺序检验**：每个目标只能和开球时间 + 90 分钟早于其截点的比赛比较。超参数（k ∈ {50, 200}、水平权重 ∈ {0, 1, 3}、校正权重 ∈ {0, 1}、下注比例 ∈ {全部, 30%, 10%}）只在开发段（02-01…07-31）按相对基准的赢盘率提升选择，然后原样在留出段（08-01…10-12）检验。基准是只用价格和盘口类型预测的赢盘率，在开发段拟合。另外用"随机邻居"作为对照。同一场比赛有多个来源 ID 时已去重。

## 结果（[`results-prototype.json`](results-prototype.json)）

开发段 25,346 个目标，留出段 14,941 个。

**按开发段选出的配置**（k=50，水平权重 3，校正权重 1，只做最强的 10%）：

| | 注数 | 赢盘率 | 基准 | 提升 | ROI |
|---|---:|---:|---:|---:|---:|
| 开发段 | 2,535 | 51.0% ±1.0 | 50.2% | +0.8 | −3.0% |
| 留出段 | 1,494 | 50.8% ±1.3 | 49.7% | +1.0 | −3.6% |

**预测值与实际市场误差的相关系数**：

| 预测方式 | 开发段 | 留出段 |
|---|---:|---:|
| 只按 μ 水平找近邻（市场在该水平上的系统偏差） | +0.020 | **+0.052** |
| 只看轨迹形状（k=200） | −0.008 | +0.021 |
| 选定配置（水平 + 形状 + 变盘校正） | +0.008 | +0.037 |
| 随机邻居（对照） | +0.002 | −0.007 |
| 一个相关系数的标准误 | 0.006 | 0.008 |

## 结论

1. **换算是成功的**：隐含净胜球把亚盘变成了连续序列，可以直接比较形状，不必再按盘口分段。
2. **轨迹形状本身几乎不能预测市场误差**：开发段为 −0.008，留出段为 +0.021，两段不一致。
3. **大部分可测到的信号来自 μ 水平本身**：也就是市场在某个让球深度上的系统性偏差，与轨迹无关。它在两段都为正，留出段更明显。
4. 选定配置在两段的赢盘率提升都约 +1 个百分点，在一个标准误以内，ROI 约 −3.5%，**目前不能作为下注规则**。

## 下一步可以尝试

- **单独研究"水平偏差"**：按 μ 深度分组，统计市场误差的方向，并在开发段和留出段分别检验。这是本次唯一在两段都为正的效应。
- **加入欧指**：欧指的平局概率可以换算出预期总进球，同一时刻的亚盘 μ 和欧指 μ 之差就是"亚欧一致性"。这需要先采集欧指数据（可先运行 `tools/probe_markets.py` 检查接口）。
- **随历史池增大重新检验**：选定配置的月度相关系数从 6 月起逐月上升（+0.015、+0.023、+0.037、+0.036、+0.042），历史池同期从 2.5 万场增加到 4.4 万场。这可能是近邻样本变多带来的，需要用之后的数据确认。

| V1 原步骤 | 连续序列版 |

**覆盖面大幅提高**：能给出方向的目标，开发段 19,672 / 25,346（78%），留出段 12,381 / 14,941（83%）；原 V1 在 T−10 约为 30%。每场的候选中位数开发段 13 场、留出段 36 场。

| 色带 | 开发段 赢盘率（基准） | 留出段 赢盘率（基准） | ROI 开发 / 留出 |
|---|---|---|---|
| 全部 | 52.4%（52.3%） | 52.7%（52.5%） | −4.0% / −4.4% |
| 绿 | 50.9%（50.6%） | 50.3%（50.5%） | −3.6% / −4.3% |
| 橙 | 51.8%（51.9%） | 50.6%（51.6%） | −4.5% / −6.3% |
| **红** | **54.8%**（54.6%） | **56.0%**（54.7%） | −4.0% / −2.8% |

- 红色赢盘率最高，和原 V1 的规律一样（原 V1 在 T−10 的红色约 55%）。但它的基准也最高，相对基准的提升只有 +0.2（开发）和 +1.3（留出），不显著。
- **原因**：红色中有 55% 落在四分之一盘的赢半一侧（.25 受让 42%、.75 让球 13%），绿色中只有 26%。邻居比赛的平局和一球小胜小负，在目标的四分之一盘上会结算成赢半或输半，并被记为 ±1，于是方向分自然偏向赢半一侧。红色的高赢盘率主要来自四分之一盘的结算结构，而不是轨迹本身的信息。

### 改用连续结果计分

为了去掉四分之一盘带来的偏差，只改变每场相似比赛的结果值 z，候选比赛、相似分权重和 α 都保持不变。三种计分在同一次运行中计算：

| 计分 | z（相似比赛 j） | 含义 |
|---|---|---|
| 二元（原） | 按目标 T−10 盘口结算：赢/赢半 +1，输/输半 −1 | 对照 |
| 净胜球 − 盘口 | (j 的实际净胜球 − 目标的 T−10 盘口) / σ | 连续值，没有赢半偏差，但仍含价格因素（偏向低水一侧） |
| 净胜球 − 隐含净胜球 | (j 的实际净胜球 − j 自己的 T−10 μ) / σ | 再去掉价格，只剩"市场错了多少" |

σ = 1.688 球（开发段"实际净胜球 − μ"的标准差）。连续值除以 σ 后代入同一个方向分公式，色带阈值不变。

| 计分 | 时段 | 全部 | 绿 | 橙 | 红 | 与市场误差的相关 |
|---|---|---|---|---|---|---:|
| 二元 | 开发 | 52.4% (+0.1) | 50.9% (+0.3) | 51.8% (−0.2) | **54.8% (+0.2)** | −0.008 |
| | 留出 | 52.7% (+0.2) | 50.3% (−0.2) | 50.6% (−0.9) | **56.0% (+1.3)** | +0.003 |
| 净胜球 − 盘口 | 开发 | 50.2% (−0.5) | 49.7% (−0.8) | 50.3% (−0.5) | 51.0% (+0.0) | −0.001 |
| | 留出 | 51.1% (+0.6) | 50.4% (+0.2) | 51.5% (+1.2) | 51.5% (+0.3) | +0.008 |
| 净胜球 − 隐含净胜球 | 开发 | 49.7% (−0.5) | 49.7% (−0.5) | 49.9% (−0.4) | 49.2% (−0.6) | −0.003 |
| | 留出 | 49.7% (−0.0) | 50.4% (+0.5) | 49.8% (+0.1) | 48.8% (−0.8) | −0.009 |

表中为赢盘率（括号内为相对价格基准的提升，百分点）。ROI 全部在 −2.6% 到 −6.2% 之间。相关系数的标准误为 0.006（开发段）和 0.008（留出段）。详细结果见 [`results-v1style.json`](results-v1style.json)。

**结论**：
- 改用连续计分后，红色不再突出，所有色带的赢盘率都在 49%–52% 之间。之前红色约 55% 的赢盘率，确实来自四分之一盘的结算方式。
- 去掉价格之后（净胜球 − 隐含净胜球），方向分与市场误差的相关在两段都约为 0，色带之间也没有差别。**按 V1 方式比对连续水位轨迹，几乎不包含价格以外的信息。**

## 临近开赛的片段轨迹是否有额外信息

假设：盘外信息（首发、伤停等）会在临近开赛时反映到水位上。如果市场到 T−10 已经完全消化，后期片段就不能预测市场误差（实际净胜球 − T−10 的 μ）；反应不足时，结果会继续朝变化方向走（应跟随）；反应过度时，结果会朝反方向走（应反向）。[`segments.py`](segments.py) 做了两种检验，结果见 [`results-segments.json`](results-segments.json)。

**1. 各片段 μ 变化与市场误差的相关**（标准误：开发 0.006，留出 0.008）

| 片段 | 开发段 | 留出段 | 只看片段内有变化的比赛（开发 / 留出） |
|---|---:|---:|---|
| 初盘 → T−360 | −0.004 | +0.012 | −0.006 / +0.015 |
| T−360 → T−120 | −0.003 | −0.006 | −0.004 / −0.008 |
| T−120 → T−60 | −0.013 | +0.006 | −0.019 / +0.009 |
| T−60 → T−30 | +0.007 | −0.015 | +0.010 / −0.021 |
| **T−30 → T−10** | **+0.010** | **+0.018** | **+0.014 / +0.025** |
| T−60 → T−10 | +0.011 | +0.002 | +0.014 / +0.002 |
| T−120 → T−10 | +0.003 | +0.004 | +0.004 / +0.005 |

- 大多数片段的相关都在 ±2 个标准误以内，而且两段之间正负翻转。
- **只有 T−30 → T−10 在两段都为正**，合计约 2.7 个标准误，呈现轻微的"反应不足"：最后 20 分钟变化之后，结果还会略微继续朝同一方向偏。但这是从 7 个片段中挑出来的，需要考虑多重检验。

**跟随/反向规则**（片段、门槛、方向在开发段按提升选，留出段检验）：最好的几条在留出段都没有稳定提升。T−30 → T−10 变化超过 0.10 时跟随，开发段 52.2%（+0.5），留出段 53.1%（+1.8，2,942 注），留出段 ROI −2.1%。

**2. 片段轨迹近邻**（每 5 分钟取一点，比较片段内形状，加上 T−10 水平，k=100）：

| 片段 | 开发段相关 | 留出段相关 | 最强 10% 的赢盘率（提升），开发 / 留出 |
|---|---:|---:|---|
| T−60 → T−10 | +0.008 | +0.017 | 48.7%（−1.8）/ 50.9%（+0.6） |
| T−120 → T−10 | −0.002 | +0.009 | 49.3%（−1.6）/ 50.4%（−0.5） |

**结论**：盘外信息基本在 T−10 前已被 Royal 价格消化。唯一的痕迹是最后 20 分钟的轻微反应不足，但幅度太小（相关约 0.01–0.02），赢盘率提升不足以抵消抽水。如果要利用它，更可能的方式是：Royal 在最后半小时变动后，在还没跟上的其他公司下注。这需要那家公司可以下注，并且有它的同步报价。

## 亚欧对照（Royal 亚盘 vs Royal 欧指）

[`euro_asia.py`](euro_asia.py) 使用 [欧指与大小球阶段数据](../euro-totals/README.md) 中的 Royal 欧指（来源 ID 545），与 Royal 亚盘按比赛 ID 连接，结果见 [`results-euro-asia.json`](results-euro-asia.json)：

- **欧指 → (μ_E, 总进球_E)**：主/平/客赔率按比例去水后，在网格上找最能复现这三个概率的独立泊松模型。拟合残差中位数只有 0.0008，三项概率几乎完全吻合。
- **亚盘 → μ_A**：T−10 的盘口和水位，用同一个总进球数换算（`supremacy.py` 现在支持任意总进球数，默认 2.7 时结果不变）。
- **差值 d = μ_E − μ_A**：d > 0 表示欧指比亚盘更看好主队。另外计算 T−60 → T−10 两者各自变化之差。

两边在 T−10 都有报价的比赛共 19,337 场：开发段 5,069 场，留出段 14,268 场。欧指数据集中在近几个月，且优先采集的是特定样本，不是随机抽样。

| | 开发段 | 留出段 |
|---|---:|---:|
| 净胜球预测的均方误差：亚盘 / 欧指 / 两者平均 | 3.18 / 3.22 / 3.19 | 2.92 / 2.96 / 2.93 |
| d 与亚盘市场误差的相关（标准误） | −0.008（0.014） | −0.021（0.008） |
| T−60 → T−10 变化差与市场误差的相关 | −0.037 | −0.001 |

- **Royal 亚盘比 Royal 欧指更准**：欧指的误差更大，和亚盘平均之后也不如只用亚盘。d 的中位数为 −0.04，说明欧指整体略微低估主队。
- **两者不一致时，亚盘略对**：d 与亚盘市场误差呈弱负相关，留出段约 2.5 个标准误。"按亚盘比欧指更看好的一方下注亚盘"在两段的提升都是 +1.6 到 +2.6 个百分点，但赢盘率约 50%，ROI 约 −4%。
- **在欧指市场下注**（买欧指相对低估的一方，按 T−10 欧赔结算）：Royal 欧指抽水中位数为 **11.9%**。命中率 60%–80%（低估的一方多为热门），ROI 在 −3% 到 −6.5% 之间（例如 |d|>0.20 时，开发段 −6.3% ±2.0%，留出段 −3.2% ±1.5%）。比单纯承担 12% 抽水的结果好，说明亚欧差确实能挑出欧指的偏差，但不足以抵消抽水。

**结论**：同一家公司的亚盘和欧指，不一致的幅度小且方向偏向亚盘正确，在 Royal 自己的亚盘或欧指上都不能盈利。亚欧对照更有希望的用法是跨公司：例如把 Royal 亚盘的 μ 与澳彩欧指比较（澳彩欧指目前约 8 千个比赛 ID），或者等欧指采集完成后再检验。

## 上盘：哪些趋势是看好，哪些是诱盘

[`upper_patterns.py`](upper_patterns.py) 从结果反推：上盘指 T−10 Royal 盘口的让球方（平手盘取主队）。每场打标签：全赢计 1（权重 1）、赢半计 1（权重 0.5）、输半计 0（权重 0.5）、全输计 0（权重 1），走盘剔除。另外按 T−10 的 μ 计算同口径的**价格隐含加权赢盘率**，以及"上盘净胜超出价格"（球）：大于 0 表示上盘打得比价格好（真看好），小于 0 表示被看好却没打出（诱盘）。

按上盘视角分组检验：盘口变化、末段（最后一个盘口）水位变化、两者的组合（升盘降水、盘不变升水等）、早段和临场的 μ 变化、T−10 上盘水位、盘口深度，共约 40 个类别。只有两段（开发 02-01…07-31、留出 08-01…10-12）同号、且合并 z ≥ 3 的才算明确，结果见 [`results-upper-patterns.json`](results-upper-patterns.json)。

**明确的趋势（都属于"看好"，没有达到标准的诱盘）**：

| 趋势 | 开发段 加权赢盘率（价格隐含）/ 超出价格 | 留出段 | 合并 z |
|---|---|---|---:|
| **盘不变、末段上盘降水** | 53.1%（51.7%）/ +0.070 球 | 54.8%（52.1%）/ +0.120 球 | 4.4 |
| 末段上盘降水（不论盘口） | 51.8%（51.5%）/ +0.034 | 53.2%（51.8%）/ +0.071 | 3.2 |
| T−10 上盘水位 < 0.80 | 54.6%（53.6%）/ +0.045 | 57.0%（53.8%）/ +0.108 | 3.3 |

- **倾向诱盘但证据不足**（两段同号、z 约 −2.3）：盘不变、末段上盘升水（−0.014 / −0.083 球）；T−10 上盘水位 ≥ 1.00（−0.042 / −0.053 球）；临场 μ 大幅走弱（−0.070 / −0.038 球）。
- **传统的盘水组合**（升盘降水、升盘升水、降盘降水、降盘升水）两段方向不一致，看不出看好或诱盘的规律。

- **按 T−10 报价买上盘**（赢盘率：全赢、赢半都算赢）：

| 趋势 | 开发段 赢盘率 / ROI | 留出段 赢盘率 / ROI |
|---|---|---|
| 盘不变降水 | 51.4% / −2.8% ±1.3% | 53.7% / −0.9% ±1.7% |
| 末段降水 | 50.5% / −4.6% | 52.2% / −2.8% |
| 上盘水位 < 0.80 | 53.7% / −4.5% | 56.1% / −1.0% |

**结论**：最稳定的信号是"盘口不动、上盘水位往下走"，上盘确实比价格打得好，而且在同一水位档内也成立。但幅度还不足以抵消抽水，ROI 在 −3% 到 −1% 之间，可以作为前瞻观察的候选，不能直接下注。

## 上盘赢球时，轨迹哪个时点最接近实际结果

[`upper_wins_volatility.py`](upper_wins_volatility.py) 按盘口深度分组。在初盘、T−1440 … T−10 各时点，从轨迹得到上盘的预期净胜球 μ_up(t)，"波动" = 实际上盘净胜球 − μ_up(t)。上盘赢（全赢权重 1，赢半 0.5）与上盘输（对照，全输 1，输半 0.5）分别统计，结果见 [`results-upper-wins-volatility.json`](results-upper-wins-volatility.json)。

**描述**（全部比赛）：

| | 初盘 | T−360 | T−60 | T−30 | T−10 |
|---|---:|---:|---:|---:|---:|
| 上盘赢：平均偏差（球） | 1.536 | 1.520 | 1.506 | 1.498 | 1.491 |
| 上盘赢：最接近的时点占比 | 27.1% | 9.2% | 8.6% | 11.6% | 18.8% |
| 上盘输：最接近的时点占比 | 32.7% | 11.0% | 6.6% | 8.7% | 14.5% |

- 上盘赢时，平均偏差从初盘到 T−10 逐步缩小，T−10 通常最接近（平手、平半两组初盘与 T−10 相当）。
- "最接近"最常落在初盘，因为初盘通常是整条轨迹里最极端的值。
- **对照显示这是按结果筛选造成的**：半一、一球、一球以上，上盘赢时最接近点偏后（T−10 占 20%–22%），上盘输时偏前（初盘占 34%–40%）。这些盘口的 μ 通常随时间朝上盘走高，赢球的比赛自然更接近后期较高的点，输球的更接近前期较低的点。这不是可以用来预测的特征。

**预测检验**：下注前已知的 μ_up(t) − μ_up(T−10)，与上盘市场误差（实际 − T−10 预期）的相关。全部比赛：开发段在 −0.013 到 +0.002 之间，留出段在 −0.025 到 −0.001 之间，都约为 0。各盘口组大多在 ±2 个标准误以内，且两段之间正负翻转。唯一两段都为负的是**平半**（开发 −0.013 到 −0.043，留出 −0.010 到 −0.038）：临近 T−10 上盘走强时，上盘略好于价格；走弱时略差，即轻微的反应不足，最多约 2 个标准误。

**结论**：在上盘赢球的比赛中，"最接近实际结果的时点"主要反映的是筛选方式本身，不能当作特征。反过来用来预测时，只在平半盘口看到很弱的延续效应，与之前"盘不变降水"和"最后 20 分钟反应不足"的发现方向一致。

## 转折点与反复程度：合成一个分数（全部比赛）

[`turning_points.py`](turning_points.py) 遵循三条原则：**始终用全部比赛**（赢球和输球一起）；用转折点和反复程度代替"最接近的时点"；把多个弱信号合成，以放大轨迹信号。结果见 [`results-turning-points.json`](results-turning-points.json)。

- **去噪**：ZigZag 转折点算法。路径反向超过 h 球（h = 0.03 和 0.08）才确认为一个转折，更小的跳动视为噪声。
- **特征**（上盘视角）：摆动次数与总摆幅、从高点回落与从低点回升、最后一段的方向和幅度、距上一个转折的时间、效率比（|净变化| / 路径总长，越接近 0 越来回反复）、高点和低点出现的时间、早段 / 临场 / 最后 20 分钟的变化、升降盘次数、盘不变降水；另有 T−10 水平、盘口深度、水位、盘口类型等"价格类"特征。
- **目标**：margin = 上盘净胜球 − T−10 隐含净胜球；profit = (上盘盈亏 − 下盘盈亏) / 2，即按 T−10 报价两边下注的实际回报差，与下注直接对应。
- **模型**：岭回归、强正则化的梯度提升树，以及两者标准化后的平均。训练时把目标截断在 ±4 球以内，减少大比分的干扰。超参数在开发段内用 5、6、7 月逐月前推验证选择，然后用 8 月以前的全部数据训练，在留出段（08-01…10-12）只评估一次。下注按模型看好的一方，在 T−10 报价上结算。

**两段都同号的单个轨迹特征**（与市场误差的相关，开发 / 留出）：盘不变降水 +0.015 / +0.025；最后一段走势 +0.021 / +0.011；最后 20 分钟 +0.010 / +0.018；从高点回落 −0.013 / −0.020；大幅摆幅（h=0.08）−0.016 / −0.019；路径总长 −0.012 / −0.012。规律是：**走势延续、盘不变降水对上盘有利；来回摆动、从高点回落对上盘不利**。

**合成后在留出段的表现**：

| 目标 / 特征 | 模型 | 留出相关（8 / 9 / 10 月） | 最强 10%：赢盘率（提升）/ ROI | 最强 20% |
|---|---|---|---|---|
| margin / 全部特征 | 岭回归 | **+0.075**（+0.038 / +0.101 / +0.087） | 51.8%（+1.3）/ −2.2% | 52.1%（+1.8）/ −1.5% |
| margin / 只用轨迹 | 岭回归 | +0.036（+0.020 / +0.048 / +0.045） | 53.3%（+0.1）/ −3.0% | 53.3%（+0.7）/ −2.5% |
| profit / 全部特征 | 平均 | +0.021（+0.028 / +0.022 / +0.003） | 56.0%（+3.4）/ −0.1% | 53.8%（+2.1）/ −2.3% |
| profit / 只用轨迹 | 平均 | +0.021（+0.030 / +0.018 / +0.008） | **56.4%（+3.4）/ +0.5%** | 53.7%（+2.0）/ −1.8% |

- margin 目标的高相关主要来自 T−10 水平和盘口深度（岭回归系数 −0.45 和 +0.37），即隐含净胜球与盘口深度的关系。它影响净胜球的大小，却几乎不影响是否赢盘，所以下注提升很小。
- 只用轨迹特征时，相关从最好的单个特征（约 0.02）提升到 0.036，每个月都为正：**合成确实放大了轨迹信号**。
- 以下注回报为目标时，最强 10% 的赢盘率达到 56%，提升 +3.4 个百分点，ROI 在 0 附近，是目前所有方案中第一次接近持平。但这是 4 种设置 × 3 个模型 × 4 个比例中最好的一格，而且月度相关逐月下降（+0.030 → +0.008），**不能视为已验证的盈利**，需要前瞻检验。
- 梯度提升树在前推验证中不如岭回归，说明信号主要是线性的、很弱，目前没有必要换更复杂的模型。

## 加入 Royal 欧指、澳彩亚盘的转折点特征

[`multi_source.py`](multi_source.py) 用相同的转折点特征（ZigZag 0.03 / 0.08、回落、回升、最后一段、效率比、时间等）处理另外两条走势：
- **Royal 欧指**：主/平/客去水后，用泊松模型换算为上盘的隐含净胜球；另加 T−10 欧指与 Royal 亚盘之差、这个差值从开盘到 T−10 的变化、欧指隐含总进球的变化；

缺少该数据的比赛填 0，并加一个"是否有数据"的标记。欧指数据大多在 8 月以后，所以改为**逐月滚动**：8、9、10 月各自用此前全部数据训练，再预测当月。模型设置沿用上一节（不再重新挑选），在同一批比赛上比较。结果见 [`results-multi-source.json`](results-multi-source.json)。

## 相似轨迹评分：只用 Royal 亚盘、以下注回报为目标，按评分分组

[`similar_score.py`](similar_score.py) 不再训练模型，而是按 V1 的方式汇总相似比赛的结果：

- 每场过去比赛的结果 z = (上盘回报 − 下盘回报) / 2（按其 T−10 报价）；z > 0 表示买上盘更赚。
- 相似空间只用 Royal 亚盘轨迹，不含 T−10 的价格水平。共三种：
  - **features**：上一节的转折点、反复程度特征，去掉水平、深度、盘口类型和水位；
  - **weighted**：同样的特征，每个特征按其与 z 的历史相关加权；
  - **path**：T−360 … T−15 各时点的 μ 减去 T−10 的 μ，即形状。
- 邻居范围分两种：所有盘口，或只取同一盘口深度。
- 评分：取 k 个最近的过去比赛（开球 + 90 分钟早于目标当天）。相似度 S = 1 − d/d₍ₖ₊₁₎，权重 w = S²，评分 D = 50 + 50·Σwz/(20 + Σw)。D > 50 时按 T−10 报价买上盘，D < 50 时买下盘。
- 配置（空间、范围、k ∈ {100, 400, 1600}，共 18 种）只在开发段按逐月相关均值选择。分组切点（D 十分位；色带：|D−50| 最强的 10% 为红、其后 20% 为橙、其余为绿）也取自开发段。留出段只检验一次。

结果见 [`results-similar-score.json`](results-similar-score.json)。

**18 种配置的相关都在 ±0.01 左右**。开发段选出的是 features、所有盘口、k=400：开发段 +0.008，留出段 +0.006（8/9/10 月 +0.012 / −0.001 / +0.005）。只取同一盘口深度的配置在留出段都变成负数。作为对照，上一节的回归模型相关约 0.02–0.036。

按 D 分组（买上盘的结果，留出段）：

| 组 | 1（最看好下盘） | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 | 10（最看好上盘） |
|---|---|---|---|---|---|---|---|---|---|---|
| 上盘赢盘率 | 49.2% | 45.7% | 48.6% | 48.1% | 48.9% | 49.0% | 48.5% | 49.1% | 51.3% | 49.7% |
| 上盘 ROI | −2.8% | −8.8% | −4.7% | −5.8% | −4.1% | −3.8% | −5.7% | −3.8% | −1.0% | −4.9% |

开发段同样没有单调关系。组 1 买上盘的结果也不差，说明评分低并不代表下盘更好。

按色带分组（买评分看好的一方）：

| 色带 | 开发：场次 / 赢盘率（提升）/ ROI | 留出：场次 / 赢盘率（提升）/ ROI | 8 / 9 / 10 月赢盘率 |
|---|---|---|---|
| 红 | 2,535 / 51.0%（−0.3）/ −4.4% | 1,773 / 51.4%（+0.5）/ −4.8% | 48.7% / 52.5% / 54.3% |
| 橙 | 5,069 / 50.5%（+0.3）/ −3.8% | 2,953 / 50.9%（+0.6）/ −3.6% | 52.9% / 50.2% / 47.5% |

红、橙、绿三组的赢盘率和 ROI 几乎一样，都约等于抽水（−4%），各月之间的起伏也在标准误以内。

**为什么相似轨迹评分不行，而回归模型能有一点**：

- 单场比赛的 z 方差接近 1，而轨迹真正带来的偏差大约只有 0.01–0.03。
- 400 个邻居的平均值，标准误约为 0.05，比信号大好几倍，评分基本是噪声。
- 距离把 26 个特征一视同仁，大部分是无关维度，"相似"的邻居在有用的维度上并不相似。
- 回归模型是在全部样本上估计每个特征的方向，相当于用几万场而不是几百场来平均，所以弱信号还能留下一点。

**结论**：用相似轨迹的回报汇总成新评分，在任何分组下都分不出赢盘率或回报的差别。如果要保留"评分 + 分组"的形式，建议把上一节回归模型的输出（只用 Royal 亚盘、profit 目标）当作评分，再按同样的十分位和色带分组。

## 曲线与曲线的相似度：净胜球与预测之差评分

[`curve_similarity.py`](curve_similarity.py) 直接比较整条曲线。盘口已经并进了曲线：每条 Royal 报价都换算成上盘的隐含净胜球 μ，变盘只是同一条曲线上的一步，不再是断点。

**曲线**：从 T−360 到 T−10，每 10 分钟取一次 μ，共 36 个点，保留绝对水平。

**相似度算法**（来自时间序列文献）：

| 名称 | 做法 |
|---|---|
| euclid | 欧氏距离，比较整条绝对曲线 |
| shape | 曲线减去 T−10 的值后再算欧氏距离，只比较形状 |
| dtw | 动态时间规整（DTW），Sakoe-Chiba 带宽 ±30 分钟，允许走势早晚错开 |
| ddtw | 导数 DTW（Keogh & Pazzani 2001），比较斜率，再加上 T−10 的水平差 |
| sbd | k-Shape 的形状距离（Paparrizos & Gravano 2015）：标准化后的互相关，平移 ±3 个点 |

- **候选**：先按 euclid 取 2,000 个最近的过去比赛（相当于下界剪枝），再用各算法重新排序。
- **加权**：取前 k 名，相似度 S = 1 − d/d₍ₖ₊₁₎，权重 w = Sᵖ。p 越大，相似度高的比赛权重越大。
- **结果口径**：
  - mu：实际净胜球 − T−10 μ；
  - line：实际净胜球 − 盘口；
  - muAdj：mu 再减去该 μ 水平的历史平均偏差。
- **评分**：评分 = Σwe / (10 + Σw)，D = 50 + 12.5 × 评分。正数说明相似比赛中上盘更准，负数说明下盘更准。
- **选择**：网格为 5 种算法 × k {50, 200, 800} × p {2, 6} × 3 种口径，共 90 种配置，只在开发段选择。

结果见 [`results-curve-similarity.json`](results-curve-similarity.json)。

**1. 与"净胜球 − μ"的相关第一次稳定为正，但这主要是换算偏差，不是市场信息。**
- 用绝对曲线的算法（euclid、dtw、ddtw）相关有 +0.04 到 +0.06，开发段和留出段每个月都为正。
- 但只按 T−10 的 μ 水平分组取平均，也能得到 +0.048。原因是泊松换算本身在不同水平有偏差，例如深让一方实际比 μ 少约 0.1 球。
- 这类偏差盘口和水位已经定价了。按"实际净胜球 − 盘口"计分时，所有配置都在 0 附近。

**2. 扣除水平偏差（muAdj）后仍有 +0.035 到 +0.04，但它不能转成下注回报。** 各算法最好配置与下注回报 (上盘回报 − 下盘回报)/2 的相关：

| 算法 | 与 muAdj 的相关（开发 / 留出） | 与下注回报的相关（开发 / 留出） |
|---|---|---|
| euclid | +0.038 / +0.041 | −0.001 / +0.010 |
| shape | +0.007 / −0.005 | −0.003 / −0.010 |
| dtw | +0.036 / +0.023 | +0.003 / −0.002 |
| ddtw | +0.034 / +0.033 | −0.001 / +0.007 |
| sbd | +0.006 / −0.010 | +0.006 / −0.008 |

这说明曲线相似的比赛确实在"净胜球偏离 μ"上相似，但这种偏离来自换算模型。例如总进球不是 2.7 时，同样的价格对应不同的 μ。盘口结算看的是价格，不是 μ，所以它不是庄家没有定价的信息。

**3. 分组**：开发段选出 euclid、k=800、p=6、muAdj。

| 色带 | 开发：赢盘率（提升）/ ROI | 留出：赢盘率（提升）/ ROI |
|---|---|---|
| 红 | 50.1%（−1.0）/ −5.8% | 52.6%（+1.3）/ −2.8% |
| 橙 | 49.4%（−0.8）/ −5.5% | 50.3%（−0.3）/ −4.8% |
| 绿 | 49.8%（−0.4）/ −5.2% | 50.1%（−0.1）/ −4.8% |

十分位分组在两段都没有单调关系。

**结论**：
- 只比较形状的算法（shape、sbd）与任何结果都无关。
- 带水平的算法（euclid、dtw、ddtw）找到的是换算偏差。
- 用任何一种曲线相似度给相似比赛加权，再按"净胜球与预测之差"评分，在下注回报上都没有区分力。
- 同一条 Royal 曲线，最后 10 分钟以前的走势已经全部反映在 T−10 的价格里。

## 升盘之后的水位：过热还是确实看好

[`after_line_up.py`](after_line_up.py) 只看最后一次变盘是升盘（朝上盘方向）的比赛：开发段 9,393 场，留出段 5,250 场。

从升盘后的第一条报价到 T−10，分组看以下几项：
- 上盘水位的变化，以及 μ 的变化；
- 升盘距 T−10 的时间；
- T−10 的上盘水位；
- 一共升了几次盘。

判断标准：
- **过热**：上盘的实际净胜球低于价格；
- **确实看好**：高于价格；
- 开发段和留出段同号，且合并 z ≥ 3，才算成立。

结果见 [`results-after-line-up.json`](results-after-line-up.json)。

| 升盘后上盘水位 | 开发：场次 / 赢盘率 / 超出价格 | 留出：场次 / 赢盘率 / 超出价格 |
|---|---|---|
| 大幅降水 ≤−0.10 | 2,312 / 49.0% / −0.045 | 1,260 / 52.0% / +0.083 |
| 降水 | 2,463 / 48.2% / −0.004 | 1,488 / 49.4% / −0.011 |
| 水平 | 3,102 / 47.2% / +0.013 | 1,758 / 46.8% / +0.017 |
| 升水 | 1,099 / 46.7% / +0.007 | 547 / 48.1% / −0.036 |
| 大幅升水 ≥0.10 | 417 / 45.2% / −0.051 | 197 / 51.1% / +0.112 |

- 没有任何一组达到"过热"或"确实看好"的标准。合并 z 都在 ±1.6 以内，只有"升盘距 T−10 为 2–6 小时"一组 z = −2.1，证据弱。
- 升盘后大幅降水，开发段略差、留出段略好；大幅升水也一样，两段方向相反。
- 按 T−10 的报价买上盘或买下盘，每一组都亏。
- 各组相对价格基准都有约 +2 到 +4 个百分点的赢盘率提升，而且各组差不多。这是这一类比赛共有的，和升盘后水位怎么走无关。

**结论**：升盘之后水位怎么走，在 T−10 的价格之外没有额外信息。和"盘不变降水"（z = +4.4）不同，一旦变过盘，之后的水位变化就看不出是过热还是看好。

## 用亚盘拆出的预期进球预测大小球

[`totals_from_asian.py`](totals_from_asian.py)。亚盘价格每场只给出一个概率，所以只能确定预期净胜球 μ，确定不了总进球；前面的换算都假设总进球为 2.7。亚盘对总进球的信息，只能来自跨比赛的规律：实力差距越大，进球往往越多。结果见 [`results-totals-from-asian.json`](results-totals-from-asian.json)。

**1. 只用亚盘（全部比赛）**：在开发段拟合，总进球 ≈ 2.50 + 0.47·|μ|。

- 与实际总进球的相关：开发段 +0.19，留出段 +0.19，R² 约 0.04。
- 平均绝对误差 1.41 球，常数预测为 1.42 球，几乎没有改进。

| \|μ\| | 0–0.25 | 0.25–0.5 | 0.5–0.75 | 0.75–1 | 1–1.5 | ≥1.5 |
|---|---|---|---|---|---|---|
| 平均总进球（开发 / 留出） | 2.62 / 2.72 | 2.64 / 2.77 | 2.74 / 2.89 | 2.87 / 2.91 | 3.07 / 3.09 | 3.61 / 3.70 |

**2. 与 Royal 大小球盘对比**：取同时有大小球 T−10 报价的 19,844 场（开发 5,205，留出 14,639）。大小球盘的预期总进球按泊松模型反推：去水后的大球概率在报出的盘口上恰好公平，四分之一盘拆成两半。

| | 开发段 | 留出段 |
|---|---|---|
| 与实际总进球相关：大小球盘 / 亚盘推算 | +0.334 / +0.201 | +0.306 / +0.188 |
| 平均绝对误差：大小球盘 / 亚盘推算 | 1.430 / 1.473 | 1.373 / 1.413 |
| 亚盘推算 − 大小球盘 与 实际 − 大小球盘 的相关 | +0.028 ±0.014 | +0.021 ±0.008 |
| 联合回归：总进球 = a + b×大小球盘 + c×亚盘推算 | b 0.91，c 0.07 | b 0.92，c 0.05 |
| 按亚盘推算方向买大/小：差距 ≥0.3 球 | 3,020 场，51.4%，ROI −1.1% | 7,247 场，50.2%，ROI −2.6% |

- 大小球盘比亚盘推算准得多，相关高出约 70%。
- 亚盘只多出一点点信息：联合回归中权重约 0.05 到 0.07，残差相关 +0.02 到 +0.03，两段都为正。
- 这点信息转成下注不够抵抽水：按亚盘推算方向买大小，赢盘率约 50%，ROI 为 −1% 到 −3.6%。

**结论**：亚盘拆出来的是预期净胜球，不是总进球。它对总进球只有"实力悬殊进球多"这一层弱关系，R² 约 0.04，远不如大小球盘本身。要预测大小球，应该用大小球盘或欧指（欧指的平局概率含有总进球信息）。
