# 新算法原型：隐含净胜球轨迹比对（Royal 亚盘）

与之前的算法无关，重新设计。只复用 `research/build_inputs.py` 的数据清洗（相同的报价、相同的已核验赛果），保证可以和以前的结果公平比较。

## 思路

亚盘每次变盘，水位都会跳变，水位序列不连续。本原型把每条报价（盘口 + 主客水位）换算成**隐含净胜球 μ**：假设主客进球服从独立泊松分布、总进球期望为 2.7，求出使去水后的价格恰好公平的预期净胜球（主减客）。

换算后，变盘不再是断点。例如平手盘主水 0.71 / 客水 0.99 → μ = +0.122；随后升盘到主让 0.25、主水 0.98 → μ = +0.147，前后连续。在 3,000 场 Royal 比赛上：

- 主队水位：换盘处的相邻变化是同盘处的 6.7 倍；
- 换算成 μ 后：只有 3.1 倍，剩下的大多是真实价格变动（庄家通常在价格变动较大时才变盘）。

欧指（主/平/客）以后可以换算到同一刻度，并多出"预期总进球"一个维度。

## 算法

| 步骤 | 内容 |
|---|---|
| 换算 | 每条 Royal 报价 → μ（预先算好查表，盘口 ±10 球以内） |
| 轨迹 | 取初盘和开赛前 1440、720、360、180、120、60、30、10 分钟时的 μ（取各时点之前最后一条报价），得到 8 段变化量，作为"形状" |
| 水平 | T−10 时的 μ |
| 变盘校正 | 发生在变盘处的 μ 变化之和、同一盘口内的 μ 变化之和、升盘次数、降盘次数 |
| 相似度 | 各特征按开发段标准差标准化后，计算加权欧氏距离 = 形状 + 水平权重 × 水平 + 校正权重 × 校正 |
| 预测 | k 个最近邻的**市场误差**均值。市场误差 = 实际净胜球 − T−10 的 μ；均值 > 0 表示同类比赛市场低估了主队 |
| 下注 | 按 T−10 的 Royal 报价买市场低估的一方；可以只做预测最强的 30% 或 10% |

**时间顺序检验**：每个目标只能和开球时间 + 90 分钟早于其截点的比赛比较。超参数（k ∈ {50, 200}、水平权重 ∈ {0, 1, 3}、校正权重 ∈ {0, 1}、下注比例 ∈ {全部, 30%, 10%}）只在开发段（02-01…07-31）按相对基准的赢盘率提升选择，然后原样在留出段（08-01…10-12）检验。基准是只用价格和盘口类型预测的赢盘率，在开发段拟合。另外用"随机邻居"作为对照。同一场比赛有多个来源 ID 时已去重。

## 结果（[`results-prototype.json`](results-prototype.json)）

开发段 25,346 个目标，留出段 14,941 个。

**按开发段选出的配置**（k=50，水平权重 3，校正权重 1，只做最强的 10%）：

| | 注数 | 赢盘率 | 基准 | 提升 | ROI |
|---|---:|---:|---:|---:|---:|
| 开发段 | 2,535 | 51.0% ±1.0 | 50.2% | +0.8 | −3.0% |
| 留出段 | 1,494 | 50.8% ±1.3 | 49.7% | +1.0 | −3.6% |

**预测值与实际市场误差的相关系数**：

| 预测方式 | 开发段 | 留出段 |
|---|---:|---:|
| 只按 μ 水平找近邻（市场在该水平上的系统偏差） | +0.020 | **+0.052** |
| 只看轨迹形状（k=200） | −0.008 | +0.021 |
| 选定配置（水平 + 形状 + 变盘校正） | +0.008 | +0.037 |
| 随机邻居（对照） | +0.002 | −0.007 |
| 一个相关系数的标准误 | 0.006 | 0.008 |

## 结论

1. **换算是成功的**：隐含净胜球把亚盘变成了连续序列，可以直接比较形状，不必再按盘口分段。
2. **轨迹形状本身几乎不能预测市场误差**：开发段为 −0.008，留出段为 +0.021，两段不一致。
3. **大部分可测到的信号来自 μ 水平本身**：也就是市场在某个让球深度上的系统性偏差，与轨迹无关。它在两段都为正，留出段更明显。
4. 选定配置在两段的赢盘率提升都约 +1 个百分点，在一个标准误以内，ROI 约 −3.5%，**目前不能作为下注规则**。

## 下一步可以尝试

- **单独研究"水平偏差"**：按 μ 深度分组，统计市场误差的方向，并在开发段和留出段分别检验。这是本次唯一在两段都为正的效应。
- **加入欧指**：欧指的平局概率可以换算出预期总进球，同一时刻的亚盘 μ 和欧指 μ 之差就是"亚欧一致性"。这需要先采集欧指数据（可先运行 `tools/probe_markets.py` 检查接口）。
- **随历史池增大重新检验**：选定配置的月度相关系数从 6 月起逐月上升（+0.015、+0.023、+0.037、+0.036、+0.042），历史池同期从 2.5 万场增加到 4.4 万场。这可能是近邻样本变多带来的，需要用之后的数据确认。

## V1 式比对与评分（连续序列，绿/橙/红）

[`v1style.py`](v1style.py) 把 V1 的比对和评分原样搬到连续的 μ 序列上（结果见 [`results-v1style.json`](results-v1style.json)）：

| V1 原步骤 | 连续序列版 |
|---|---|
| 严格/近似候选：首末盘口相同、关键水位差 ≤0.05 / ≤0.10 | 不要求盘口相同；初盘 μ、T−10 μ、μ 最低点、μ 最高点、最近 15 分钟的 μ 变化，各项差 ≤0.04 / ≤0.08（相当于 0.05 / 0.10 水位）；整体和最近的变化方向一致（±0.02） |
| 点序相似分 S（按点位进度对齐后，同向变化所占比例） | 同一公式直接用于整条 μ 序列，不需要按盘口分段；两条序列都至少 5 个不同点才计分。快速实现与 V1 原函数在 300 组随机序列上的差异小于 1e−13 |
| 方向原分 D = 50 + 50·Σwz/(α+Σw)，w=(S/100)²，α=20 | 相同；z 为邻居比赛的实际比分**按目标比赛 T−10 盘口**结算的主队结果（赢/赢半 +1，输/输半 −1，走盘不计） |
| 展示分与色带：绿 <10、橙 10–25、红 ≥25 | 相同 |

时间顺序同前：只和开球 + 90 分钟早于截点的比赛比较，按 T−10 的 Royal 报价结算。

**覆盖面大幅提高**：能给出方向的目标，开发段 19,672 / 25,346（78%），留出段 12,381 / 14,941（83%）；原 V1 在 T−10 约为 30%。每场的候选中位数开发段 13 场、留出段 36 场。

| 色带 | 开发段 赢盘率（基准） | 留出段 赢盘率（基准） | ROI 开发 / 留出 |
|---|---|---|---|
| 全部 | 52.4%（52.3%） | 52.7%（52.5%） | −4.0% / −4.4% |
| 绿 | 50.9%（50.6%） | 50.3%（50.5%） | −3.6% / −4.3% |
| 橙 | 51.8%（51.9%） | 50.6%（51.6%） | −4.5% / −6.3% |
| **红** | **54.8%**（54.6%） | **56.0%**（54.7%） | −4.0% / −2.8% |

- 红色赢盘率最高，和原 V1 的规律一样（原 V1 在 T−10 的红色约 55%）。但它的基准也最高，相对基准的提升只有 +0.2（开发）和 +1.3（留出），不显著。
- **原因**：红色中有 55% 落在四分之一盘的赢半一侧（.25 受让 42%、.75 让球 13%），绿色中只有 26%。邻居比赛的平局和一球小胜小负，在目标的四分之一盘上会结算成赢半或输半，并被记为 ±1，于是方向分自然偏向赢半一侧。红色的高赢盘率主要来自四分之一盘的结算结构，而不是轨迹本身的信息。

### 改用连续结果计分

为了去掉四分之一盘带来的偏差，只改变每场相似比赛的结果值 z，候选比赛、相似分权重和 α 都保持不变。三种计分在同一次运行中计算：

| 计分 | z（相似比赛 j） | 含义 |
|---|---|---|
| 二元（原） | 按目标 T−10 盘口结算：赢/赢半 +1，输/输半 −1 | 对照 |
| 净胜球 − 盘口 | (j 的实际净胜球 − 目标的 T−10 盘口) / σ | 连续值，没有赢半偏差，但仍含价格因素（偏向低水一侧） |
| 净胜球 − 隐含净胜球 | (j 的实际净胜球 − j 自己的 T−10 μ) / σ | 再去掉价格，只剩"市场错了多少" |

σ = 1.688 球（开发段"实际净胜球 − μ"的标准差）。连续值除以 σ 后代入同一个方向分公式，色带阈值不变。

| 计分 | 时段 | 全部 | 绿 | 橙 | 红 | 与市场误差的相关 |
|---|---|---|---|---|---|---:|
| 二元 | 开发 | 52.4% (+0.1) | 50.9% (+0.3) | 51.8% (−0.2) | **54.8% (+0.2)** | −0.008 |
| | 留出 | 52.7% (+0.2) | 50.3% (−0.2) | 50.6% (−0.9) | **56.0% (+1.3)** | +0.003 |
| 净胜球 − 盘口 | 开发 | 50.2% (−0.5) | 49.7% (−0.8) | 50.3% (−0.5) | 51.0% (+0.0) | −0.001 |
| | 留出 | 51.1% (+0.6) | 50.4% (+0.2) | 51.5% (+1.2) | 51.5% (+0.3) | +0.008 |
| 净胜球 − 隐含净胜球 | 开发 | 49.7% (−0.5) | 49.7% (−0.5) | 49.9% (−0.4) | 49.2% (−0.6) | −0.003 |
| | 留出 | 49.7% (−0.0) | 50.4% (+0.5) | 49.8% (+0.1) | 48.8% (−0.8) | −0.009 |

表中为赢盘率（括号内为相对价格基准的提升，百分点）。ROI 全部在 −2.6% 到 −6.2% 之间。相关系数的标准误为 0.006（开发段）和 0.008（留出段）。详细结果见 [`results-v1style.json`](results-v1style.json)。

**结论**：
- 改用连续计分后，红色不再突出，所有色带的赢盘率都在 49%–52% 之间。之前红色约 55% 的赢盘率，确实来自四分之一盘的结算方式。
- 去掉价格之后（净胜球 − 隐含净胜球），方向分与市场误差的相关在两段都约为 0，色带之间也没有差别。**按 V1 方式比对连续水位轨迹，几乎不包含价格以外的信息。**

## 临近开赛的片段轨迹是否有额外信息

假设：盘外信息（首发、伤停等）会在临近开赛时反映到水位上。如果市场到 T−10 已经完全消化，后期片段就不能预测市场误差（实际净胜球 − T−10 的 μ）；反应不足时，结果会继续朝变化方向走（应跟随）；反应过度时，结果会朝反方向走（应反向）。[`segments.py`](segments.py) 做了两种检验，结果见 [`results-segments.json`](results-segments.json)。

**1. 各片段 μ 变化与市场误差的相关**（标准误：开发 0.006，留出 0.008）

| 片段 | 开发段 | 留出段 | 只看片段内有变化的比赛（开发 / 留出） |
|---|---:|---:|---|
| 初盘 → T−360 | −0.004 | +0.012 | −0.006 / +0.015 |
| T−360 → T−120 | −0.003 | −0.006 | −0.004 / −0.008 |
| T−120 → T−60 | −0.013 | +0.006 | −0.019 / +0.009 |
| T−60 → T−30 | +0.007 | −0.015 | +0.010 / −0.021 |
| **T−30 → T−10** | **+0.010** | **+0.018** | **+0.014 / +0.025** |
| T−60 → T−10 | +0.011 | +0.002 | +0.014 / +0.002 |
| T−120 → T−10 | +0.003 | +0.004 | +0.004 / +0.005 |

- 大多数片段的相关都在 ±2 个标准误以内，而且两段之间正负翻转。
- **只有 T−30 → T−10 在两段都为正**，合计约 2.7 个标准误，呈现轻微的"反应不足"：最后 20 分钟变化之后，结果还会略微继续朝同一方向偏。但这是从 7 个片段中挑出来的，需要考虑多重检验。

**跟随/反向规则**（片段、门槛、方向在开发段按提升选，留出段检验）：最好的几条在留出段都没有稳定提升。T−30 → T−10 变化超过 0.10 时跟随，开发段 52.2%（+0.5），留出段 53.1%（+1.8，2,942 注），留出段 ROI −2.1%。

**2. 片段轨迹近邻**（每 5 分钟取一点，比较片段内形状，加上 T−10 水平，k=100）：

| 片段 | 开发段相关 | 留出段相关 | 最强 10% 的赢盘率（提升），开发 / 留出 |
|---|---:|---:|---|
| T−60 → T−10 | +0.008 | +0.017 | 48.7%（−1.8）/ 50.9%（+0.6） |
| T−120 → T−10 | −0.002 | +0.009 | 49.3%（−1.6）/ 50.4%（−0.5） |

**结论**：盘外信息基本在 T−10 前已被 Royal 价格消化。唯一的痕迹是最后 20 分钟的轻微反应不足，但幅度太小（相关约 0.01–0.02），赢盘率提升不足以抵消抽水。如果要利用它，更可能的方式是：Royal 在最后半小时变动后，在还没跟上的其他公司下注。这需要那家公司可以下注，并且有它的同步报价。
