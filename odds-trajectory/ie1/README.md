# IE1 盘赔意图–价值方案

整理日期：2026-10-13。IE1（Intent → EV）把截图里的“庄家意图 M 分类 + 泊松模型 + EV + 比分参考”分析写法改成固定公式。赔率获取沿用库里 [V1 方案](../v1/README.md) 的大球小球/懂球帝聚合接口、T−10 截点和同公司轨迹规则，并用已上传的[欧指与大小球阶段快照](../euro-totals/README.md)做了回测。

**结论先行：** 回测里，截图那类“升盘挺水/临场一致/欧亚背离”信号单独使用都赢不过抽水。唯一在开发期和留出期都为正的是 **用 Royal T−10 公允价去衡量澳彩同时刻的亚盘报价**。所以 IE1 的投注候选只来自这一项，M 信号保留为报告里的诊断，不影响下注。所有结果都是赛后回看重算，正式下注前还要积累前瞻记录。

## 2. 赔率获取（沿用 V1）

| 市场 | 接口 `type` | Royal companyId | 澳彩 companyId | 数据来源 |
| --- | --- | --- | --- | --- |
| 亚盘 | asia | 3 | 1 | [轨迹快照](../README.md) `odds_history` |
| 大小球 | size | 3 | 1 | [欧指/大小球快照](../euro-totals/README.md) `quotes` |
| 欧指 | euro | **545** | **80** | 同上 |

接口为 `https://www.daqiuxiaoqiu.com/sport-data/soccer/biz/dqd/v1/match/odds/detail/{match_id}?companyId={id}&type={asia|size|euro}`。欧指的公司 ID 与亚盘/大小球不同，`quotes.SOURCE_CID` 已固定该映射。

截点和清洗规则：

- 决策截点 C = 开球 K − 600 秒（T−10），所有公司、所有市场一致；只用 `ts ≤ C` 且 `ts < K` 的赛前非滚球报价。
- 亚盘直接调用 V1 的 `points()`：同分钟顺序须有来源证据，换盘歧义整窗不可用，水位须在 (0,3]，让球方以“受”字判定。
- 大小球/欧指只取 `quote_valid=1`、`prematch=1`，并采用严格分钟口径（源分钟起点 + 60 秒 ≤ C）。同分钟有冲突的分钟不取价；若截点前**最后一个**可用分钟有冲突，该市场判为不可用，不挑一个价格替代。
- 香港水位换成十进制赔率时加 1；欧指本身是十进制。
- 赛果只用核验过的常规 90 分钟比分（规则见 [字段说明](../DATA_DICTIONARY.md#时间与分析口径)）。
- 同场多个来源 ID 按 `fixture_group` 去重，只留一条。

## 3. 公允价模型

1. **去水**：两项盘（亚盘、大小球）按比例去水；欧指用幂次法去水（减轻热门/冷门偏差）。
2. **比分矩阵**：Dixon–Coles 泊松，λ主 = (T + S)/2，λ客 = (T − S)/2，T 为总进球，S 为净胜球，ρ 固定 −0.05，比分截到 10 球后重新归一。
3. **拟合**：用参考公司（Royal）截点时的亚盘 + 大小球两条价格反解 (T, S)，两条方程两个未知数，正常可精确命中。缺大小球时 T 用先验 2.6 并下调一档；欧指只用于 M1，不参与公允价。
4. **亚盘/大小球结算**：四分之一盘拆成两半各 0.5 注；赢的概率 W、走盘概率 P，单位期望收益 = W × 赔率 + P − 1；对应“不含走盘的胜率” = W/(1 − P)。

## 4. 信号 M1–M7（当前只做诊断）

每个信号取值在 [−1, 1]，正值表示看好主队（或大球）。盘口和水位都先经模型换算成“隐含净胜球/总进球”再比较，因此“升盘不挺水”自然比“升盘降水”移动小，不需要另写规则。

| 信号 | 定义 | 尺度 | 开发期单变量结果 |
| --- | --- | --- | --- |
| M1 欧亚盘赔背离 | 欧指 + 大小球折算净胜球 − 亚盘折算净胜球 | ÷0.15 球 | β=+0.068 球，t=1.93 |
| M2 全程盘路移动 | Royal 首条有效报价 → 截点的隐含净胜球变化 | ÷0.25 球 | β=+0.054 球，t=2.16 |
| M3 大小线移动 | Royal 大小球首条 → 截点的隐含总进球变化 | ÷0.25 球 | β=−0.031 球，t=−1.02 |
| M4 跨公司分歧 | Royal 截点净胜球 − 其余公司均值 | ÷0.15 球 | β=+0.019 球，t=0.40 |
| M5 临场一致移动 | 截点前 60 分钟 Royal 净胜球变化 × 同向公司比例 | ÷0.15 球 | β=+0.052 球，t=1.79 |
| M6 信息面 | 人工录入的净胜球/总进球修正，各限 ±0.15 球，录入时间须早于截点 | — | 无法回测 |
| M7 V1 同轨方向 | (D − 50)/50 × min(1, 有效样本/5)，按上盘方向换成主客 | — | 本次未接入 |

开发期把 M2、M4、M5 一起回归时三者都不显著（|t| < 2），按事先约定系数全部置 0。追随强信号（|s| ≥ 0.5）在 Royal 截点价下仍亏 3–5%，只是比反着买少亏。也就是说，这些移动大部分已经反映在 T−10 价格里。修正上限仍保留在参数中（净胜球、总进球各 ±0.25 球），某个信号以后通过验证时再打开。

M6 是唯一会实际改变模型的信号，人工录入就会生效，并参与否决：如果信息面方向与候选相反，该候选不出。

## 5. 决策规则

1. **阻断**：Royal 亚盘有效赛前报价少于 3 条；目标赛事属女足/青年/预备/友谊；赛事不在 V1 [一级赛事名单](../v1/rules/first-tier-competitions.json)。
2. **降一档提示**：杯赛/国家队/洲际赛事；缺大小球（总进球用先验）；Royal 末报价距截点超过 30 分钟；欧亚折算净胜球相差超过 0.25 球；拟合残差过大；信息面录入晚于截点。
3. **候选**：用（公允价 + 已启用修正）给**澳彩**截点亚盘报价定价，按 EV 从高到低取第一个。大小球、欧指和 Bet365 的 EV 也会列出，但标为“仅观察”。
4. **否决**：已启用信号或 M6 的方向与候选相反，且反向最强值 ≥ 0.5。
5. **等级**：EV ≥ 4% 为 A（1 单位），EV ≥ 2% 为 B（0.5 单位）；有任何提示时降一档，C 只记录、不下注。每场只取首次合格信号，锁定当时的盘口和水位，与 V1 Royal 登记规则一致。

报告格式沿用截图：市场公允价 → 庄家意图 M1–M7 → 模型与比分参考 → 各公司 EV → 结论/推荐，见 `python odds-trajectory/ie1/code/demo.py`。

## 6. 回测（赛后回看）

数据：亚盘轨迹快照（2026-10-13）+ 欧指/大小球阶段快照（2026-10-13 16:36，Royal 仅采到约 9%）。三项 Royal 市场齐全且比分已核验的真实比赛共 19,962 场，可拟合的 19,201 场；开球时间为 2026-06 至 2026-10。事先约定分段：**开发期**为 2026-09-01（北京时间）之前，11,073 场；**留出期**为之后，8,128 场。完整输出见 [BACKTEST_REPORT.json](BACKTEST_REPORT.json)。

**公允价校准（Royal T−10）**

| 分段 | 亚盘主队 Brier | 平均模型 P / 实际命中 | 大球 Brier | 平均模型 P / 实际命中 | 盲买主/客/大/小 ROI |
| --- | ---: | --- | ---: | --- | --- |
| 开发 | 0.2482 | 50.0% / 50.3% | 0.2491 | 50.4% / 49.7% | −3.9% / −5.6% / −5.9% / −4.0% |
| 留出 | 0.2481 | 50.1% / 49.4% | 0.2492 | 50.4% / 50.1% | −5.7% / −3.7% / −4.9% / −5.0% |

模型与实际命中率差距在 1 个百分点以内，盲买约亏 4–6%，正好是抽水。

**跨公司价值：Royal 公允价 × 澳彩 T−10 亚盘**

| EV 门槛 | 开发 n | 开发 ROI（±SE） | 留出 n | 留出 ROI（±SE） |
| --- | ---: | --- | ---: | --- |
| 全部报价 | 9,062 | −6.3% ±0.9% | 6,338 | −5.6% ±1.1% |
| ≥ 0% | 385 | +2.5% ±4.4% | 214 | +7.3% ±5.8% |
| ≥ 2% | 126 | +11.5% ±7.6% | 73 | +19.8% ±9.8% |
| ≥ 4% | 49 | +11.7% ±12.4% | 36 | +32.7% ±12.4% |
| ≥ 6% | 21 | +0.8% ±19.5% | 14 | +31.0% ±23.3% |

同样做法用在澳彩大小球：开发期为正（EV ≥ 2%：+12.5%，n=68），留出期转负（−7.3%，n=41），因此大小球不进入投注市场。

**整套引擎（仅留出期，按上述规则运行，含阻断/降档/否决）**

| 范围 | A 级 n / ROI | B 级 n / ROI | C 级（不下注）n / ROI | 下注单位 / 盈亏 |
| --- | --- | --- | --- | --- |
| 不限赛事（关闭一级名单门槛） | 22 / +43.7% ±14.1% | 29 / +28.1% ±15.3% | 9 / −8.9% | 36.5 / +13.69 |
| 只限一级赛事（默认） | 12 / +30.7% ±20.9% | 12 / −0.3% ±25.9% | 3 / −38.0% | 18.0 / +3.66 |

默认的一级赛事门槛下，留出期只有 24 注，结果基本是噪声，不能拿来证明有效。不限赛事时样本多一些、结果也更好，说明澳彩跟价慢在非一级联赛更常见。是否放开一级名单，应等前瞻记录出来再定。

使用这些数字时注意：

- 2%/4% 门槛是同时看过两段结果后确定的。只看开发期也会选 2%/4%（开发期 ≥ 6% 反而变差），但留出期已不算完全干净。真正的检验要靠 2026-10-13 之后的前瞻登记。
- 留出期 EV ≥ 2% 只有 73 场，ROI 与 0 相差约 2 个标准误。样本小，波动大。
- 价值来自澳彩跟价慢。数据是赛后采集的，不能证明 T−10 时这些澳彩报价真的能下单、能下多少；实际可成交的价格和限额要在前瞻记录里核对。
- 欧指/大小球只采到约 9%，而且优先采了已有亚盘覆盖的比赛，样本不是随机抽样。
- 同一场多个市场、多家公司不是独立样本；表中每场每侧只计一次。

## 7. 文件与运行

**每天怎么执行，见 [RUNBOOK.md 执行手册](RUNBOOK.md)**：首次联网核对报文字段、T−10 自动扫描与登记、信息面录入、结算、复盘和转实盘门槛。

```text
ie1/
  README.md               方案说明（本文）
  RUNBOOK.md              执行手册
  BACKTEST_REPORT.json    回测输出
  code/
    ie1.py                命令行：probe / run / note / settle / stats / offline / replay
    source.py             限速抓取、停机规则、原始报文存档、赛程读取
    parse.py              报文解析（中文盘口、进球线、无年份时间）
    quotes.py             接口与公司 ID 映射、T−10 路径
    pricing.py            去水、Dixon–Coles、结算概率、(T,S) 拟合
    signals.py            M1–M7 与修正量
    engine.py             公允价 → 修正 → EV → 门槛 → 中文报告
    ledger.py             前瞻台账（冻结输入、首个合格推荐锁定、结算）
    settle.py             锁定条款结算
    dataset.py            连接两份快照，构建每场 T−10 盘口簿与 90 分钟赛果
    backtest.py           校准、信号研究、跨公司价值、留出期整套回测
    demo.py               合成数据示例
    parameters.json       版本、截点、系数、门槛、抓取与报文字段、实盘门槛
  examples/               赛程 CSV、比分 CSV、手工赔率 JSON 样例、完整报告示例
  tests/test_ie1.py       单元与端到端测试（模拟接口）
```

需要 Python 3.10 或更新版本，只用标准库。在仓库根目录运行：

```powershell
python -m unittest discover -s odds-trajectory/ie1/tests
python odds-trajectory/ie1/code/demo.py
python odds-trajectory/ie1/code/ie1.py offline --input odds-trajectory/ie1/examples/offline_example.json
python odds-trajectory/ie1/code/backtest.py --cache fixtures.pkl --out report.json --workers 4
```

回测大约需要 10 分钟和 2 GB 内存。`--cache` 会保存连接后的盘口簿，第二次运行可跳过读取快照。
