# T−10 算法与 Royal 自动模拟规则

规则依据为 `odds_similarity_service.py`、`odds_point_scoring.py`、`direction_score_journal.py`、`paper_signal_auto.py` 与 `PAPER_ROYAL_T10_AUTO.md` 的当前实现。实际自动登记入口是 `RoyalT10AutoBets`。本文区分“计算截点”与“模拟记录资格”，与 [V1 算法说明](ALGORITHM.md)配套。

## 1. 固定截点和执行时间

自动阶段为 T−120、T−60、T−30、T−10。晚启动只安排最新到期阶段。T−10 的计算截点固定为 `C=K−600秒`，K 为已核验开球时间；目标与历史样本均采用提前量 600 秒。

只有来源报价时间 `ts≤C` 且 `ts<K` 的赛前记录参与，观察窗口从首条有效赛前报价到 C。延迟运行时 C 不移动，不把已发生的滚球补入赛前轨迹。

自动 T−10 有开球后 600 秒执行宽限：服务在 `now≥K+600` 时拒绝新执行或完成写入。已保存日记的资格检查允许已知 `generated_at≤K+600`，这是存量证据检查的边界差别。开球后才生成的结果明确标注延迟，不能当成开赛前实际可用。

生成时间已知时还须满足 `C≤generated_at≤K+600`，且不超过检查时刻 now+30 秒。旧导入日记的生成时间可为空，必须保留未知，不能升级为前瞻证据。

## 2. 补采、新鲜度与完整点序

配置补采时优先补采，同公司分别读取报价。补采超时可沿用本地已保存的截点前报价，并保留 `refreshWarning`/回退标记；来源冲突不能以本地回退消除。

当前没有“末报价必须在截点前 N 分钟以内”的硬门槛。`dataAgeMinutes=round((C−末报价时间)/60,1)` 为披露指标，不等于已确认行情最新。不能额外套用人工模拟入口的150秒比赛状态或30秒比分门槛。

匹配特征至少 3 条有效赛前报价；动态点序可排序门槛与盘段覆盖按[算法说明](ALGORITHM.md#5-固定盘口的点序相似分)执行。T−10 的 `recentDelta` 锚点为 C−900 秒，等于开球前 25 分钟及以前当前盘口段中的真实点。

## 3. Royal 自动登记目标

| 项目 | 规则 |
| --- | --- |
| 公司/阶段/类型 | company_id=3、stage=10、kind=auto |
| 赛日 | 北京时间当天12:00至次日12:00；默认起点2026-10-07赛日 |
| 赛事资格 | 使用[一级赛事精确名称名单](rules/first-tier-competitions.json) |
| 名称处理 | NFKC；先取 ·、｜、竖线之前的标签，删除空白并转小写 |
| 阻断目标标签 | 女、青年、少年、后备、预备、友谊、Uxx、women/youth/reserve/friendly 等 |
| 方向 | D>50 上盘，D<50 下盘；abs(D−50)≤1e−8中性不登记 |
| 色带 | 非中性 green/orange/red 均可，按展示分一位小数后的距离判断 |
| 单位 | 每个真实比赛首次合格信号登记1单位 |

“Royal 收录”等 attention 标签不代替一级赛事名单。上述目标资格不限制历史比对池；历史样本仍可混合跨联赛、青年、女足、友谊赛等类型。

## 4. 橙色有效样本门槛

2026-10-11追加：只有 Royal 橙色自动登记要求 **未舍入 effectiveN≥5**。绿色、红色维持既有资格，不统一追加这个门槛。

必须同时满足：

- 日记和冻结 payload 的 effectiveN 均为非负有限数，数值完全一致。
- 两份 sampleCount 均为非负整数且完全一致。
- effectiveN≤sampleCount+1e−8；effectiveN<5 时为样本不足。

未知、非法、存储不一致与已知样本不足分别留原因。sampleCount 不能代替 effectiveN。已有回执/记录不因此重放或删除；若首个橙色不足，而后续新快照达到5且仍合格，可按“首次合格、每场一次”登记。

`groupConflict` 是组间方向分歧诊断，不是当前自动登记排除条件。颜色强、样本多都不构成已验证的胜率承诺。

## 5. 冻结证据校验

必须核验任务未被替代、评分有限且在[0,100]、非中性方向存在、色带与 D 一致、C=K−600、北京时间赛日一致、队伍方向与盘口一致。

冻结盘口须为有限四分之一整数、绝对值≤20；自动登记的冻结字段校验要求主客水位均在 `(0,20]`，报价时间≤C且<K。上游轨迹清洗更严格，使用 `(0,3]`，两层门槛不要混写。

payload 的原分必须等于日记原分；方向状态不得为不足；冻结 `feature.last` 的 line/home/away/ts 必须与日记字段逐一一致。拒绝：

- 回顾评分、当前 V1 配置下保留的 V2 影子快照。
- 公司错误，来源核验 conflict/unavailable，blocked 报价。
- 身份、赛程、来源 ID、真实比赛身份或生成窗口冲突。
- 缺失/非法评分、中性、颜色/方向不符、未来报价、被冻结报价不一致。

同场多个已核验来源 ID 归一；比较各来源首份有效冻结 Royal T−10 报价。来源有冲突或冻结报价时间/盘口/主客水位不一致时拒绝，不能从当前行情挑一条替代旧冲突。被替代任务不能登记，但其已保存报价仍可参与来源冲突审计。

## 6. 首次合格、锁定条款和留痕

锁定首个合格信号对应的队伍、盘口及同一条 Royal 报价的水位，不取当前主盘口，也不从澳彩借水位。后续颜色升级或方向反转不追加、不覆盖。

同时用真实比赛身份与已保存 recordIds 检查重复；已有投注跳过。处理回执与新记录在同一事务中提交。日记按版本及输入哈希追加，旧证据与原始条款保留。

历史补录标记“信号历史补录（模拟）”，确认时间为实际写入时间；后续标记“信号自动记录（模拟）”。模拟初始口径为0–0；最终结算使用锁定盘口及已核验常规90分钟比分（含补时，不含加时和点球）。迟到结果、旧导入和补录均保留实际生成/写入时间及证据状态。

## 7. 回放与原始线上信号

固定 V1 的 Royal 历史回放采用 p=2、α=20，原回放审计只接受开赛前已完成的原始 T−10 任务，其范围比后来允许开球后10分钟完成的线上规则更窄。它属于回顾重构，并明确 `originalDirectionIssued=False`。

后续按日期、颜色、延迟或警告分组的审计脚本范围不成为新的线上筛选条件。单靠已发布轨迹快照重算，不能称重现了原始任务当时发出的方向；还需对应冻结输入、版本、日记和生成时刻。

本仓库只发布算法与规则资料。运行时的登记、来源核验与事务留痕由本地应用执行，本文不自动创建模拟记录。
